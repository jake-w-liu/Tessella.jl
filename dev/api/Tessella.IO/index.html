Tessella.IO

Tessella.IO — Module
IO

Mesh file I/O: gmsh MSH v2.2 and v4.1 (ASCII) read/write, ASCII/binary STL ingest for boundary surface meshes, and a lightweight .geo parameter/structure and mesh-field scanner.

The MSH round-trip contract is connectivity preservation: reading a mesh and writing it back — in either format version — must reproduce the same topology, verified by MeshTypes.mesh_crc. gmsh allows arbitrary node/element tags; we relabel to a compact 1:N on read (connectivity is invariant under a consistent relabel) while preserving physical-group tags.

read_geo_params scans declarations without executing CAD operations: global mesh sizing, physical groups, numeric list variables, and the raw background-field graph.

Tessella.IO.GeoParams — Type
GeoParams

What read_geo_params can extract from a .geo without a geometry kernel: mesh_size_min/max/factor, random_seed, physical_groups (a (dim, tag) => name map for named groups, dim ∈ {0:point,1:curve,2:surface,3:volume}), raw fields, and the background_field tag. Named declarations with no explicit tag receive a tag from the global Physical-group namespace. Unnamed Physical declarations are checked by the scanner but omitted from the name map. Missing numeric mesh options are represented by NaN; no background field is tag 0. boundary_layer_fields preserves the distinct, deduplicated BoundaryLayer Field = ... declarations; these are mesher controls, not background scalar fields. geometry_tolerance stores Geometry.Tolerance when it is a finite constant numeric expression, or NaN when absent. mesh_boundary_layer_fan_elements stores the final Mesh.BoundaryLayerFanElements value (default 5). Automatic-field declarations also snapshot Mesh.MeshSizeFromCurvature in their GeoFieldSpec, since Gmsh uses that global at field construction time.

Tessella.IO.read_bdf — Method
read_bdf(path; max_nodes, max_elements, max_file_bytes) -> BdfFile

Read a Nastran bulk data file (.bdf/.nas). GRID cards supply nodes (blank or zero cp only — nodes on alternate frames are skipped with a warning) and CBAR, CBEAM, CROD, CTUBE, CTRIA3, CTRIA6, CQUAD4, CQUAD8, CTETRA[4|10], CPENTA[6|15], CHEXA[8|20] and CPYRA[5|13] cards supply elements, with the property-id field becoming the elementary and physical tag. Fixed 8-column and comma-delimited free formats are supported along with *-suffixed 16-column large fields, +/* continuation lines, D/d exponents and implied-exponent reals; $ comments are stripped. INCLUDE rejects loudly, ENDDATA ends the deck, and all other non-element cards are skipped.

Tessella.IO.read_brep — Method
read_brep(path; max_file_bytes) -> BrepFile

Read the envelope census of an OCCT CASCADE Topology .brep text dump: the versioned header, the Locations/Curve2ds/Curves/Polygon3D/ PolygonOnTriangulations/Surfaces/Triangulations declared counts, and a per-kind TShapes census verified against its declared total. Tessella.IO.read_diff — Method
read_diff(path; max_nodes, max_elements, max_file_bytes) -> DiffFile

Read a Diffpack GridFE .diff file: a free-form banner scanned for the Number of space dim./Number of elements/Number of nodes/ Max number of nodes in an element/Boundary indicators: headers (substring anchors at fixed token positions, like the pinned strstr + sscanf sequence), a #-led node section of num ( x , y , z ) [k] b1 .. rows whose boundary-indicator lists are consumed but unused upstream, and a #-led element section of num type subdomain n1 .. nk records over the ten Elm* type names. Each type's arity comes from its own name (the declared maximum width is informational only) and node placement follows the pinned readDIFF mapping tables; the subdomain column becomes the elementary entity tag. Missing headers, malformed records, non-positive node numbers, duplicate or dangling node references, unknown element types, negative counts and short lines are errors; duplicate nodes warn and keep the first coordinates.

Tessella.IO.read_geo_params — Method
read_geo_params(path; max_file_bytes=typemax(Int)) -> GeoParams

Scan a gmsh .geo/.geo_unrolled for mesh-sizing options, Physical group declarations, and Field[...]/Background Field statements. Deterministic, finite arithmetic expressions can use Pi, prior scalar variables and Gmsh's pure numeric functions, including in explicit Physical-group tags and Field[...] tags. Numeric lists support zero-based indexing, cardinality, copies, concatenation, bounded selection, and checked assignment or compound mutation. Finite constant Gmsh list ranges use start:end[:increment] order and are expanded with a strict resource bound in recognized numeric field options and field selectors; known numeric list variables are normalized there as well. Entirely numeric Physical memberships containing ranges are checked but remain geometry data. Geometry-derived Physical memberships remain opaque to this scanner and are evaluated by execute_geo. Named declarations populate physical_groups; a nonempty name without an explicit tag receives the next tag from the global Physical namespace. Unnamed declarations receive the same scanner checks without adding a name. Read-only dynamic tag allocators are evaluated while their Point, shared geometric-region, or Field namespace remains fully tracked. SetMaxTag Point|Curve|Surface|Volume updates the associated checked counter. Built-in can lower a counter; OpenCASCADE only raises it. Tracked Boolean operand Delete releases the operand and its hidden boundary entities and re-tags the result boundary at the lowest free tags; any other topology change makes the affected allocator unavailable. Reads use the greatest counter among activated factories. If/ElseIf/Else/EndIf conditionals, For ranges, the bounded While extension, Function/Macro definitions and Call replay follow upstream's lexer-level skip semantics: dead branches emit no diagnostics, ElseIf conditions still evaluate, loop bodies re-scan per iteration, function bodies register at Return and re-scan at Call. Option reads, random/external functions, CSG and Boolean geometry are deliberately not evaluated. Numeric field options are normalized to literals; geometric references and string or point-dependent field expressions remain source strings.

Tessella.IO.read_inp — Method
read_inp(path; max_nodes, max_elements, max_file_bytes) -> InpFile

Read an Abaqus .inp input deck's mesh sections: *NODE records (id, x, y [, z], D/d exponents accepted) and *ELEMENT, TYPE=name blocks mapping through _INP_ELEMENT_TYPES (suffix modifiers stripped; unrecognized types warn once and are skipped). *ELSET/ELSET= memberships become physical tags: Physical<Dim><tag> names pin the tag, Volume|Surface|Line|Point<tag> names become elementary entities and other names get the lowest free tag in their dimension plus a physical name. *NSET blocks are validated but not transported, GENERATE ranges are expanded, *INCLUDE/INPUT= decks reject and all other keywords are skipped. ** lines are comments; dangling node references and malformed records are errors.

Tessella.IO.read_ir3 — Method
read_ir3(path; max_nodes, max_elements, max_file_bytes) -> Ir3File

Read an Iridium .ir3 file — the inverse of write_ir3: a 33 format line, a numVertices num2D num3D or numVertices numElements header, index x y z vertex rows (the index column becomes node_tags) and self-describing num tag numVert v1 ... vk element records. The tag column is read as the elementary entity tag — the writer's element_tag_type=1 default; tag-type-2 decks are indistinguishable. Three-count headers fix each record's dimension by section; the single-count form resolves one dimension for the whole deck — an arity set representable in exactly one dimension fixes it, while a set working in both falls back to a node-planarity tiebreak (planar → surface). numVert maps to the lowest-order catalog element of the resolved dimension, preferring complete over serendipity cells. Bad format lines, non-positive counts, duplicate/unknown vertices, negative tags and truncated records are errors. Upstream ships only the writer; this reader is a Tessella extension.

Tessella.IO.read_mesh — Method
read_mesh(path; max_nodes, max_elements, max_file_bytes) -> MeshFile

Read an INRIA/Medit .mesh file (versions 1–4, Dimension 2 or 3). Tessella.IO.read_meshb — Method
read_meshb(path; max_nodes, max_elements, max_file_bytes) -> MeshFile

Read an INRIA/Medit binary .meshb file (versions 1–4, Dimension 2 or 3, little- or big-endian). Keyword-coded sections carry the same records as the ASCII .mesh sections: Vertices, Edges[P2|P3|P4], Triangles[P2|P3|P4], Quadrilaterals, Tetrahedra[P2|P3|P4] and Hexahedra map to their Gmsh types; the trailing ref becomes the elementary entity tag and, when positive, the physical tag. Unrecognized keywords are skipped through their next-keyword offset; dangling vertex references, malformed records and inconsistent offsets are errors. Returns the same MeshFile contract as read_mesh. Gmsh itself has no .meshb route; this is the libMeshb/GMF binary counterpart of the Medit reader.

Tessella.IO.read_msh — Method
read_msh(path; tessella_extensions=false,
         max_nodes=typemax(Int32), max_elements=typemax(Int32),
         max_entities=typemax(Int32),
         max_blocks=typemax(Int32),
         max_physical_names=typemax(Int32),
         max_name_bytes=1_048_576,
         max_file_bytes=typemax(Int)) -> MshFile

Read a gmsh ASCII .msh file (format 2.2 or 4.1). Node/element tags are relabelled to a compact 1:N; per-element physical tags are preserved. Resource limits are checked against section headers before record-sized allocation, and the parsed simplex mesh is validated before it is returned. MSH4 files without the optional $Entities section receive neutral implicit entities. Repeated $Entities and $Elements sections are accumulated; repeated physical names must agree. Tessella.IO.read_neu — Method
read_neu(path; max_nodes, max_elements, max_file_bytes) -> NeuFile

Read a Gambit neutral .neu file: the CONTROL INFO size record, NODAL COORDINATES (id x y [z], NDFCD 2 or 3), ELEMENTS/CELLS (id type npts connectivity, Gambit codes 1–7 with hex/pyramid corner swaps), ELEMENT GROUP blocks (ordinal → elementary entity, GROUP: number → physical tag, name → physical name) and BOUNDARY CONDITIONS blocks (element type side records resolved to faces/edges through the Gambit side tables; the set ordinal → elementary, the Physical<Dim><tag> fallback name or the ordinal → physical tag). Tessella.IO.read_vtk — Method
read_vtk(path; max_nodes, max_elements, max_file_bytes) -> VtkFile

Read a legacy ASCII VTK file. DATASET UNSTRUCTURED_GRID files carry POINTS n float|double, CELLS m size (per-cell node count and 0-based indices) and CELL_TYPES m; DATASET POLYDATA files carry POLYGONS records whose type is inferred from the node count or LINES polylines (split into lin2 segments, each record on its own curve entity under the upstream centerline physical group). VTK cell types map to Gmsh types for point, line, triangle, quadrangle, tetrahedron, hexahedron, wedge, pyramid, the quadratic edge-only and complete quadratic families (23/28, 25/29, 26/32) and quadratic pyramid, plus the complete-order Lagrange families (68–74) whose order is inferred from the node count; any other cell type, node-count mismatch, BINARY payload or XML dialect rejects loudly. Field data sections are ignored like the pinned reader. Node ordering is the exact inverse of write_vtk/the model-view VTK export lattice.

source
Tessella.IO.read_wrl — Method
read_wrl(path; max_nodes, max_elements, max_file_bytes) -> WrlFile

Read a VRML 1.0/2.0 .wrl file's indexed geometry. Each IndexedFaceSet/IndexedLineSet contributes its Coordinate/Coordinate3 point list (V2 requires the Shape { geometry ... } nesting; V1 consumes the current sibling Coordinate3) and the -1-separated coordIndex faces. Two-index faces become line cells; V2 faces of three or more indices become a sliding-window alternating-orientation triangle strip, V1 three-index faces a triangle, four a quad, and five or more a vertex-0 fan — all matching the observed upstream element walk. Elements land on one entity per dimension per geometry set, node tags are the 1-based source point indices, and missing -1 terminators, comma-free separators and multi-shape files are accepted as documented leniencies where upstream's reader is stricter or buggy. Index overruns, coord USE references, malformed structure, and files with no indexed geometry are errors.

Tessella.IO.read_xao — Method
read_xao(path; max_file_bytes) -> XaoFile

Read the envelope of a gmsh XAO .xao CAD file: the <XAO> version and <geometry> name, the <shape format> + embedded CASCADE Topology dump census (as a BrepFile, via read_brep's parser), the <topology> index→TShape entity map (with optional names; entity tag = index+1 like upstream), <groups> physical groups resolved to member entity tags, and <fields> rows. Separately stored shapes retain their declared format without an embedded census. API.open/API.merge materialize native CAD geometry and bind its topology, entity names and physical groups.

Tessella.IO.write_bdf — Method
write_bdf(path, mesh)

Write a Mesh or MixedMesh as a Nastran bulk data file (small-field 8-column format): a BEGIN BULK/ENDDATA deck of GRID cards followed by CBAR, CTRIA3, CTRIA6, CQUAD4, CQUAD8, CTETRA, CTETRA10, CPENTA, CPENTA15, CHEXA, CHEXA20, CPYRA and CPYRA13 element cards whose PID field carries the physical tag (blank when zero). GRID ids and element ids keep the external node/element tags when present. Second-order cards split over +-id continuation lines in the MSC layout. Point cells are skipped (the format has no point element); every other unmapped type — 3-node lines, 9-node quads, tets beyond order 2 and special records — rejects loudly. Coordinates must fit the 8-column field.

Tessella.IO.write_celum — Method
write_celum(path, mesh)

The CELUM deck (<name>_f faces file, <name>_s vertices file) requires per-vertex exterior normals and principal curvatures, which upstream obtains by reparametrizing each node on its CAD surface (reparamMeshVertexOnFace + f->normal(param)/f->curvatures(param,...)). Tessella's foreign-format projection carries no parametric surface, so this writer rejects truthfully instead of fabricating curvature data.

Write a Mesh/MixedMesh as a TOCHNOG input deck: the upstream literal preamble, node <i> x [y [z]] rows at %.16g for the mesh dimension, element <num> <tochnog-type> n… records, physical-group element-set and node-set sections. Tessella.IO.write_diff — Method
write_diff(path, mesh; scaling_factor=1.0)

Write a Mesh or MixedMesh as a Diffpack GridFE .diff file, matching the pinned GModel::writeDIFF/MVertex::writeDIFF/MElement::writeDIFF records: the Number of space dim. = 3 banner, Number of elements/ Number of nodes counts, the All elements are of the same type/ Max number of nodes in an element summary, the N Boundary indicators: line, num ( %25.16E , %25.16E , %25.16E ) [k] b1 .. bk node rows and num type subdomain n1 .. nk element records for the ten Elm* types. scaling_factor multiplies coordinates like the upstream Mesh.ScalingFactor. Only cells of the highest meshed dimension with a Diffpack type string are emitted — lines, prisms, pyramids, points and every other family are skipped like upstream (nodes used by skipped cells are still written and carry boundary indicators). Nodes referenced by no cell are not written. When any entity declares physical tags the subdomain column repeats the element once per entity physical (and unphysical entities emit none — still counted in the header, like upstream); with no declared physicals the subdomain is the elementary entity tag. Boundary indicators are the sorted physical tags (or entity tags when no physicals exist) of the top-dimension-minus-one entities containing each node; the header lists their union. Upstream's read/write node permutations are not mutual inverses for the non-involution layouts, so a .diff round trip permutes quad8/quad9, tet10 and hex8/hex20/hex27 connectivity exactly like Gmsh itself.

Tessella.IO.write_meshb — Method
write_meshb(path, mesh; version=0)

Write a Mesh or MixedMesh as an INRIA/Medit binary .meshb file (keyword-coded Vertices, Edges/Triangles/Quadrilaterals/Tetrahedra/ Hexahedra and the P2–P4 variants, End), the binary counterpart of write_mesh. version selects the libMeshb encoding: 1 (32-bit reals/indices/offsets), 2 (64-bit reals, 32-bit indices/offsets), 3 (64-bit reals/offsets, 32-bit indices) or 4 (64-bit everywhere); the default 0 picks version 3, upgrading to 4 when a section count exceeds Int32 — the same upgrade rule libMeshb applies. Tessella.IO.write_msh — Method
write_msh(path, mesh; version=2.2, physical_names=Dict(),
          gmsh_compatible=true)

Write mesh to a gmsh ASCII .msh file. version is 2.2 or 4.1. physical_names maps (dim, tag) => name. Per-cell physical tags come from the mesh's *_tag vectors; cells are grouped into entity blocks by (dim, tag). Gmsh 4.15.2 treats backslashes and tabs literally but cannot preserve quoted or line-breaking physical names, and truncates serialized names beyond 128 bytes. Unsafe or oversized names are rejected. Set gmsh_compatible=false only for a Tessella-to-Tessella escaped-name round trip, and read that file with read_msh(...; tessella_extensions=true).

Tessella.IO.write_neu — Method
write_neu(path, mesh)

Write a Mesh or MixedMesh as a Gambit neutral file: a CONTROL INFO header (NUMNP/NELEM/NGRPS/NBSETS/NDFCD/NDFVL, always NDFCD=NDFVL=3 so the upstream reader can parse it), NODAL COORDINATES, the top-dimension cells in ELEMENTS/CELLS (hexes and pyramids written in Gambit corner order), one ELEMENT GROUP section per distinct physical tag (including a GROUP: 0 set for untagged cells, so foreign readers do not drop them) and one BOUNDARY CONDITIONS section per dimension-1 physical group whose cells resolve to parent-cell faces/edges through the Gambit side tables (unresolvable members warn once and are skipped; unphysical boundary cells are dropped like upstream). Tessella.IO.write_stl — Method
write_stl(path, mesh; binary=false)

Write the surface facets of a Mesh or MixedMesh as an ASCII STL file (Gmsh's default STL encoding), or as little-endian binary STL when binary=true. Binary facets carry Float32 coordinates and normals, and a zero attribute count. Coordinates outside the finite Float32 range and nondegenerate facets that collapse under Float32 rounding reject before the destination is replaced. Tri3 blocks emit one facet each; Quad4 blocks split on their first-third vertex diagonal — (a,b,c) then (a,c,d) — matching upstream's deterministic quad triangulation. Facet normals are recomputed from the wound vertices; degenerate facets emit a zero normal.

STL is a surface-only format, so volume element blocks (any msh_dimension 3 type) and surface types STL cannot carry (quadratic triangles, higher-order quads, special records) reject loudly instead of being silently dropped. Lower-dimension point and line records carry no surface data and are skipped, as upstream's face-only traversal does. A mesh with no surface elements at all is an error — an empty solid would look like a successful export of nothing.

Tessella.IO.write_su2 — Method
write_su2(path, mesh)

Write a Mesh or MixedMesh as an SU2 native file: NDIME from the highest element dimension (2 or 3), NPOIN with 0-based trailing indices, NELEM with the top-dimension cells, and NMARK boundary lists grouping the dimension-1 cells by physical tag (MARKER_TAG is the physical name, or a physical_<tag>/unmarked fallback). Physical tags on the top-dimension cells and physical names of un-named groups are not representable and are dropped.

Tessella.IO.write_vtk — Method
write_vtk(path, mesh; title="Tessella mesh")

Write a Mesh or MixedMesh as a legacy ASCII VTK file: a # vtk DataFile Version 2.0 header, a free-form title line, ASCII, DATASET UNSTRUCTURED_GRID, POINTS n double coordinates (%.17g, so a read-back is bit-exact), CELLS m size with the per-cell node count and 0-based connectivity in VTK order, and CELL_TYPES m. Unlike the model-view writer the legacy CELLS encoding is always used — the pinned model writer has no OFFSETS/CONNECTIVITY variant.
