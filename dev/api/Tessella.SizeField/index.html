Tessella.SizeField

Tessella.SizeField — Module
SizeField

Scalar and mesh-size fields. The field graph follows Gmsh's composition model: generic scalar fields such as DistanceField feed size-producing fields such as ThresholdField, while MinSize, MaxSize and BoundedSize compose or constrain the result.

field_value(field, x, y, z) evaluates any scalar field. size_at(field, ...) is deliberately restricted to AbstractSizeField and guarantees a finite, strictly-positive mesh size before a meshing kernel can consume it.

Tessella.SizeField.AutomaticMeshSizeField — Type
AutomaticMeshSizeField(surface; n_nodes_per_circle=20, hmin, hmax)
AutomaticMeshSizeField(surfaces; n_nodes_per_circle=20, n_points_per_gap=0,
                       hmin, hmax, hbulk, gradation=1.1, smoothing=true,
                       features=true, source_points, source_point_sizes,
                       source_segments, source_segment_sizes, source_fields)

Native analogue of Gmsh AutomaticMeshSizeField over one or more triangulated surfaces. Surface vertices carry prescribed sizes: per-vertex maximum principal curvature kmax — estimated per input mesh by the same published Rusinkiewicz 2004 construction upstream's CurvatureRusinkiewicz runs on each model face (per-triangle least-squares second-fundamental tensors, vertex-frame projection, 2×2 eigensystem) — yields h = clamp(2π /(n·kmax), hmin, hmax), the upstream 2π/(nodePerTwoPi·kmax) rule. n_nodes_per_circle = 0 disables the curvature channel here; upstream's nodePerTwoPi > 0 test instead gates its whole octree refine pass (bulk refinement included) — a divergent bundle the per-channel form below deliberately avoids, since its only observable difference is on the nPointsPerGap > 0 feature channel, which keeps working here. Each input mesh keeps its own vertex set, so curvature estimates never bleed across crease boundaries (upstream's shared-vertex merge likewise resolves per-face, last face winning).

On a vector/tuple of surfaces the union additionally applies the remaining prescription stages of Gmsh's HXT field as discrete analogues:

  • features && n_points_per_gap > 0 — local feature size between non-incident triangles whose closest point lies within 60° of the candidate's normal cone ("thin layers"), contributing h_gap = dist / n_points_per_gap — upstream's featureSize writes the same edgeLength / nPointsPerGap prescription onto Delaunay edges spanning a medial-axis pole; the nearest-facing-triangle detector is the honest stand-in for that Delaunay/medial machinery, which cannot be reproduced without the restricted HXT tetrahedralizer (and cannot be verified — the shipped oracle binary lacks HXT+P4EST). Triangles incident to the query vertex — including co-located duplicate vertices on neighbouring surfaces — are excluded so shared edges are not phantom gaps. Note: upstream binds features to a flag it never reads — the probe gates on nPointsPerGap > 0 alone there; here the documented option is honoured, so features=false suppresses the stage (a strict superset of upstream's behaviour).
  • hbulk — fallback size where neither curvature nor a gap prescribes one (default 1.3·span/20, the size upstream assigns to octree cells that never touched the surface; upstream additionally coarsens all-untouched families — value-equal here since such leaves store the same hbulk).
  • smoothing && gradation > 0 — relaxation so sizes grow by at most max(0, gradation−1) per unit of distance, applied along union edges before the sizes are stored (the surface-edge part of upstream's gradation model).

Non-surface size sources feed the same octree through optional keyword arguments — the analogue of the extra vertex/sizeFunction channels the upstream forest accepts (forestOptions->sizeFunction, featureSizeAtVertices; upstream's field itself exposes no source options, so these are constructor-level here):

  • source_points — a 3×n matrix, a list of point tuples, or one or more Meshes (their nodes) prescribing source_point_sizes (scalar or per-point; default hbulk, upstream's unspecified-lc behaviour). A leaf containing a point refines while its edge exceeds the smallest prescribed size inside it, then stores that minimum — the same feature-like (unhalved) rule the upstream cell test applies to featureSizeAtVertices.
  • source_segments — (a,b) endpoint pairs or Meshes (their segments) prescribing source_segment_sizes (scalar or per-segment). A leaf whose box overlaps a segment refines the same way, so a curve source tightens the field along its whole length without dense sampling.
  • source_fields — one or more scalar AbstractFields (DistanceField wrapped by ThresholdField, MathEvalField, ExtendField, …) sampled at cell centers and corners: a leaf refines while its edge exceeds the smallest sample, then stores the clamped center sample. This is the upstream sizeFunction hook made effective — upstream only assigns it and never refines on it — so a source feature narrower than a leaf's nine-point stencil can still be under-resolved (documented bound; upstream's bulk grid can likewise miss features smaller than hbulk).

The sizes are stored on an adaptive octree over the 1.3·span cube centred on the surface bounding box — the analogue of upstream's p4est/HXT map, which keeps one size "at the center of the cells". A leaf intersected by surface triangles refines while its edge exceeds min(hc/2, hf) — the exact upstream curvatureRefineCallback criterion h > fmin(hc / nElemPerCell, hf) with nElemPerCell = 2 (the curvature prescription is halved, the feature prescription is not), still bounded by edge ≥ hmin — and stores the clamped min(hc, hf); non-surface sources refine with the feature-like (unhalved) target. Triangle touchers are detected by exact SAT triangle/box overlap — strictly tighter than upstream's triangle-AABB R-Tree candidate test, which can flag cells the surface never reaches. The unconditional edge ≤ hBulk cover pass upstream runs (refineToBulkSizeCallback) is not reproduced: untouched leaves carry hbulk at coarser granularity, which is value-equal but cheaper than the O((span/hbulk)³) uniform grid. The tree is 2:1 face-balanced, and smoothing applies the volumetric gradation — the upstream limitSize analogue, h[q] = min(h[q], h[p] + (gradation−1)·(edge_p+edge_q)/2) over face-adjacent leaf pairs (upstream's exact per-pair axial distance), solved as a multi-source shortest path so the result is order-independent; upstream converges a finite-difference gradient sweep to the same family of bounds within a 1e-3 tolerance.

Evaluation is cell-local: field_value descends to the leaf containing the query (out-of-domain points clamp onto the boundary leaf; upstream returns an unfound 1e22 sentinel outside its padded domain) and returns its stored size clamped to [hmin, hmax] — piecewise constant across the domain. Upstream's scalar operator() evaluates size + ds·(p−c) per leaf — a first-order correction by the residual finite-difference gradient left over from its smoothing iterations (bounded by (gradation−1+1e-3)·edge/2, and identically zero when smoothing=false) — and takes the minimum over leaves containing a boundary point; the piecewise-constant leaf value kept here agrees at every cell centre and differs inside a leaf by at most that bounded tilt.

Default sizes follow upstream's resolution order: the model scale is the largest surface bounding-box span padded by 1.3, hmin defaults to L/1000, hbulk to L/20, and an unset hmax follows hbulk — so an explicit hBulk above span/20 is not silently clamped away.

DistanceField(; points=(), segments=(), triangles=())
DistanceField(mesh; include_points=true, include_segments=true, include_triangles=true)

Euclidean distance to the union of discrete point, line-segment and triangle targets. Curves and surfaces in Gmsh's Distance field are internally discretized before querying; Tessella accepts that discrete representation directly and evaluates segments and triangles exactly instead of replacing them with a second point-cloud approximation.

Unlike a mesh-size field, a distance field can legitimately return zero. Feed it through ThresholdField or BoundedSize before passing it to a mesher.

Tessella.SizeField.PostViewField — Type
PostViewField(coords, values; points=nothing, lines=(), triangles=(),
              quadrangles=(), tetrahedra=(), hexahedra=(), prisms=(),
              pyramids=(), crop_negative=true, use_closest=true,
              reference_tolerance=1e-6, max_nodes=1_000_000,
              max_elements=1_000_000)

Gmsh PostView on first-order list data. coords is 3×n. Scalar values can be a length-n vector or a 1×n matrix; vector and tensor values are 3×n and 9×n matrices; multiple time steps pass a c×n×steps array and select one with time (all steps are validated, the selected step is stored). Connectivity is 1-based and can be an arity-by-element matrix or an iterable of index tuples. When no connectivity is supplied, every column remains a point element, preserving the original API. With explicit topology, point elements are absent unless supplied through points.

Queries use Gmsh's first-order reference-element interpolants for points, lines, triangles, planar quadrangles, tetrahedra, hexahedra, prisms and pyramids. If no element contains the query, use_closest=true retries at the closest active node. Scalar data returns the interpolant; vector data returns the Euclidean norm of the interpolated vector, matching the scalar operator of Gmsh's PostView field. The scalar operator of tensor data is GMSH_MAX_SIZE, as Gmsh does; tensor views are instead evaluated through metric_raw and metric_at, or wrapped as a PostViewAnisoField so the field composes with anisotropic combinators and refine_to_size. Non-positive scalar results become GMSH_MAX_SIZE when crop_negative=true.

Element records built through PostViewField(records) may additionally carry a .scheme (Post.PosScheme-compatible) custom-interpolation basis — the SL2/INTERPOLATION_SCHEME high-order .pos extension. Scheme elements are stored as _PVSchemeCells: the value basis evaluates Σₜ coefval[i,t]·Mₜ and an optional coefgeo/expgeo pair curves the reference map, inverted per query by Newton iteration. Mixed component counts and non-planar first-order quadrangles are still rejected. Vector norms use overflow-safe arithmetic; results that are not representable as finite Float64 values are rejected by the field-result contract.

Tessella.SizeField.PostViewField — Method
PostViewField(records::AbstractVector; time=1, crop_negative=true,
              use_closest=true, reference_tolerance=1e-6,
              max_nodes=1_000_000, max_elements=1_000_000)

Build a PostViewField from element-typed view records — objects exposing .kind (:point, :line, :triangle, :quadrangle, :tetrahedron, :hexahedron, :prism, :pyramid), .coords (3×arity), and .values (c×arity or c×arity×steps, c ∈ (1,3,9)), as produced by Post.PosElement. Every record's nodes are appended to the shared node list (so coincident nodes across records stay independent, like Gmsh's flat list data), and the record's kind selects the element family. All records must share the component count c and time-step count; records of a different component kind must be filtered beforehand, matching Gmsh's tensor-then-vector-then-scalar precedence. Step data are validated for every step; time selects the active step (1-based).

Tessella.SizeField._gmsh_bbox_characteristic_length — Method
_build_geo_field(params::GeoParams, entities, root_field; kwargs...) -> AbstractField

Build the parsed .geo Background Field and apply Mesh.MeshSizeMin, Mesh.MeshSizeMax, and Mesh.MeshSizeFactor in Gmsh order. entities is either a dictionary or a callable resolving (dimension, reference) to a Mesh (or a vector of meshes). Symbolic references such as surface_group[] are normalized to surface_group; numeric entity tags are also accepted.

The strict builder covers the coordinate-only catalog directly and delegates the five model/view-backed kinds through context_fields. Unsupported field kinds, options, expressions, missing entities, cycles, and invalid references raise ArgumentError instead of being ignored.

base_dir resolves relative Structured.FileName paths, model_bbox supplies the six-coordinate model bounds needed by Octree, and the resource keywords bound structured samples and octree cells. model_characteristic_length overrides the model scale used for Gmsh's default finite-difference step. Otherwise degenerate bounds are padded with Gmsh 4.15.2's FinishUpBoundingBox rules; geometry_tolerance supplies the corresponding geometry tolerance (with Gmsh's effective minimum of 1e-6). entity_boundaries and entity_embedded map (dimension, tag) entities to their CAD topology for Restrict and Constant expansion. context_fields is a tag-indexed dictionary override or a (spec, config, entities, params) callable for fields that require model/view state unavailable in GeoParams: Extend, PostView, AttractorAnisoCurve, BoundaryLayer, and AutomaticMeshSizeField. The resolver is responsible for interpreting the typed, validated config and must return an AbstractField. The legacy three-argument callable form remains accepted after the same option validation.

geo_postview_context(views::AbstractVector; time=1)

Tessella.SizeField.metric_aniso_cap — Method
metric_aniso_cap(m::Metric3, aniso_max) -> Metric3

Bound m's physical anisotropy hmax/hmin = sqrt(λmax/λmin) — Mesh.AnisoMax in the BGM metric — to aniso_max by coarsening the over-fine directions: eigenvalues larger than λmin·aniso_max² are clamped down to that cap while λmin is unchanged, so the capped metric never exceeds the coarsest requested size and never refines. Returns m unchanged when aniso_max is non-finite, <= 0 or >= 1e33 (the upstream unbounded default), when λmin <= 0 (the positive-definiteness check stays with callers), or when m is already within the bound.

Tessella.SizeField.metric_at — Method
metric_at(field::PostViewField, x, y, z) -> Metric3

Symmetric-projection Metric3 of a tensor PostViewField at (x,y,z): the nine interpolated components are averaged as (tᵢⱼ + tⱼᵢ)/2 and checked for positive definiteness, matching the SMetric3 Gmsh builds from PostView tensor data (for symmetric input — the only data this field is meant for — the projection is exact). A query with no containing element returns the identity metric, mirroring Gmsh's default-constructed SMetric3; Gmsh's CropNegativeValues does not apply to tensor data, so it is ignored here as well. Throws ArgumentError when the field is not tensor-valued or the projected tensor is not positive definite.

Tessella.SizeField.metric_raw — Method
metric_raw(field::PostViewField, x, y, z) -> Union{NTuple{9,Float64},Nothing}

Interpolate the nine components of a tensor PostViewField at (x,y,z), returning the row-major components exactly as stored in the view (Gmsh's searchTensorClosest result). A use_closest field falls back to the closest active node, like Gmsh; otherwise an uncovered query returns nothing. The components are not symmetrized — apply metric_at for a symmetric positive definite Metric3, or inspect raw[3i+j] directly. Throws ArgumentError unless the field holds 9-component data.

Tessella.SizeField.vector_raw — Method
vector_raw(field::PostViewField, x, y, z) -> Union{NTuple{3,Float64},Nothing}

Interpolate the three components of a vector PostViewField at (x,y,z), returning the raw vector exactly as stored in the view — Gmsh's OctreePost::searchVector result, used (un-normalized) by boundary-layer Extrude View[i] directions. A use_closest field falls back to the closest active node like Gmsh's searchVectorClosest; otherwise an uncovered query returns nothing (upstream's false return, which callers translate to a zero vector). Throws ArgumentError unless the field holds 3-component data.
